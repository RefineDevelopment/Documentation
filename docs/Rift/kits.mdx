# Kits

Rift has three kinds of kit.

| Kind | Who makes it | Used for |
| --- | --- | --- |
| **FFA kits** | Staff | Selectable shared-pit kits or assigned loadouts for independent arenas |
| **Player kits and layouts** | Players, in the kit editor | Saved arrangements of FFA arena kits and fully custom RTP kits |
| **Presets** | Bundled with Rift | Starting points with IDs beginning `preset-` |

The bundled presets are `crystal`, `cart`, `diamond`, `diamondsmp`, `mace`, `nethpot`, `spearmace`, and `uhc`.

## Shared-pit kits

With `ffa-pit.enabled: true`, players use `/kit` (alias of `/ffakit`) at the lobby
or their pit's safe spawn to choose a kit and its default or a saved layout.
All allowed kits fight together in the active map. Kit and current layout choices
remain through deaths and map rotations; the kit preference also survives reconnects.
The shared picker has no five-second choice deadline, and combat-tag restrictions
still apply.

Create each loadout with `/ffakit create <id>` while carrying its inventory, armor,
and offhand. Set `ffa-pit.kits` to a list of IDs in menu order, or `[]` to allow
every saved FFA kit. There is no fixed kit count; both menu styles have pages.

```text
/ffakit setprice sword 0
/ffakit setprice archer 250
```

New kits are free. A positive price adds a permanent unlock purchase with a
confirmation screen. Owned kits do not charge again, and ownership survives
deaths, map changes, reconnects, and restarts. Keep at least one allowed kit free.
Renaming or updating a kit preserves its owners; reusing a deleted ID preserves
that ID's owners too. Prices apply to shared-pit selection.

See [Shared FFA pit](shared-ffa-pit.mdx) for map rotation, coin rewards, NPC entry,
configuration, and troubleshooting. Use `/ffakit edit <id>` at the lobby to edit
layouts while the pit is enabled.

## FFA arena kits

Each independent FFA arena outside `ffa-pit.maps` has its own assigned kit. Players joining that arena use its
loadout and can choose one of their saved arrangements of those items. Their
layout choice applies to that arena entry and subsequent respawns.

### Set an arena's kit

Build the loadout in your inventory, including armor and offhand, then save it
for an existing FFA arena:

```text
/arena setkitffa <arena>
```

For example, save a crystal loadout for `cpvpffa`, then equip a sword loadout
and save it for `swordffa`:

```text
/arena setkitffa cpvpffa
/arena setkitffa swordffa
```

These commands require `rift.admin.arena`. Each saves the current inventory,
armor, offhand, and selected hotbar slot into that arena's kit. To change an
existing loadout, fetch it, adjust your items, and save it back:

```text
/arena getkitffa cpvpffa
/arena setkitffa cpvpffa
```

The generated kit ID is `arena-<arena-id>`, and the assignment is stored as
`ffaKit` in `data/ffa/<arena-id>.json`. `setkitffa` saves the assignment for you;
you do not need to edit JSON or set a global default. Changing a kit's items
invalidates layouts saved against its previous contents, so players arrange
and save new layouts for the updated kit.

### Player layouts

With the shared pit disabled, players at spawn use `/ffakit` to choose an arena kit and one of its **five
saved layout slots** to arrange in the kit room. Layouts are saved per player
and per kit. `/ffakit select <id>` and `/ffakit edit <id>` open that kit's layout
picker; `/ffakit reset <id>` resets its first layout slot. The ID here is the
kit ID, such as `arena-cpvpffa`, rather than the arena ID.

Entering FFA offers saved layouts for the kit assigned to that arena, plus
**Use Arena Default** for the staff-defined arrangement. Empty slots cannot be
selected for use. The choice lasts five seconds; expiry applies the arena's
default arrangement. Respawns retain that entry's choice. `/ffakit` inside FFA
reopens the pending choice while its timer is active. Players can arrange the
assigned kit's items; choosing a layout does not change which kit the arena uses.

The kit and layout pickers use native dialogs by default. Set `dialogs.ffa-kits`
or `dialogs.enabled` to `false` in `config.yml` to use chest menus, customized
under `ffa-kits.types` and `ffa-kits.layouts` in `menus.yml`. Players can also
choose hotbar selection in `/settings`; that preference remains available with
either interface. See [Menus & Dialogs](menus-and-dialogs.mdx).

### Manage kit records

The `/ffakit` staff commands manage the underlying kit records. Arena kits
created with `setkitffa` can be managed using their `arena-<arena-id>` IDs:

| Command | Description |
| --- | --- |
| `/ffakit create <id>` | Create a kit from your inventory, armor, and offhand. |
| `/ffakit setinventory <id>` | Replace a kit's items with your inventory. |
| `/ffakit load <id>` | Put a kit's items in your inventory so you can edit them. |
| `/ffakit seticon <id> [material]` | Set the icon to your held item or a material. |
| `/ffakit rename <id> <name>` | Set the display name. |
| `/ffakit setdefault <id>` | Set the fallback kit; this does not change an arena's assigned kit. |
| `/ffakit setprice <id> <price>` | Set the shared-pit permanent unlock price; `0` makes it free. |
| `/ffakit delete <id>` | Delete the kit. |

These staff commands require `rift.admin.ffakit`. Creating a standalone kit with
`/ffakit create` does not assign it to an arena. Use `/arena setkitffa <arena>`
for an independent arena, or include the standalone kit in `ffa-pit.kits` for
shared-pit selection.

## Kit editor

Players open `/kiteditor` to choose FFA layouts or RTP custom kits, then enter
the [kit room](spawn-and-kit-room.mdx) to edit. An edit is a session that must be
confirmed or canceled at the confirm and cancel stations. Nothing saves until then.

Mode, custom-slot, and preset selectors follow `dialogs.kit-editor` and the
global `dialogs.enabled` switch. Chest versions are configured under
`kit-editor.modes`, `kit-editor.slots`, and `kit-editor.presets` in `menus.yml`.
The FFA button then follows the separate `dialogs.ffa-kits` switch: one kit opens
its layouts directly, while several kits open the type picker first.

RTP custom-slot and preset chest screens have pages. The preset screen keeps the
selected custom slot and offers **Edit Current Layout / Start Empty** on every
page. Choosing a preset starts an unsaved edit: Confirm saves to that slot;
Cancel keeps the previous kit. Item renaming, shulker editing, and the separate
`/getpremadekit` picker retain their interfaces.

| Setting (`kiteditor.yml`) | Default | Effect |
| --- | --- | --- |
| `max-custom-kits` | `8` | Custom kits per player, clamped to 1–45 |
| `allow-offhand-edit` | `true` | Allow editing the offhand slot |
| `protection.isolate-players` | `true` | Players in the room can't see each other |
| `protection.prevent-damage` | `true` | No damage in the room |
| `protection.prevent-block-changes` | `true` | No block changes in the room |

Add your own items to the editor's supply menus under `custom-items` (`weaponry`, `armor`, `utilities`, `consumables`, `arrows`, `blocks`, `potions`).

Players can also use `/kitroom` to open the supply menu, and `/kiteditor` subcommands such as `trims`, `enchant`, `shulker`, and `rename` for the held item.
