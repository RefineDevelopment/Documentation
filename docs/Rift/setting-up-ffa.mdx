# Set up FFA

FFA arenas are void worlds. Rift creates the world, you build the arena in it, then you finish setup by saving its clean map. Install and enable **WorldEdit or FastAsyncWorldEdit** before using FFA. Run these commands in-game with `rift.admin.arena` (included in `rift.admin`).

<Steps>

1. Create the arena:

   ```text
   /arena create <id> ffa
   ```

   Rift creates a void world, loads it, and teleports you in. IDs may contain letters, numbers, `_` and `-`.

2. Build the arena. A 3x3 bedrock platform is placed at `0, 64, 0` to stand on. Turn this off with `arenas.spawn-platform: false` in `config.yml`.
3. Stand where players should spawn and run `/arena setspawn <id>`.
4. Stand in one corner of the playable area and run `/arena setmin <id>`, then in the opposite corner and run `/arena setmax <id>`. You must be inside the arena's world. Include the spawn and the air above the floor, keep the bounds within the world's build height, and avoid overlapping other FFA arenas in the same world. New arenas start with broad bounds; tighten them around your map.
5. Choose the kit (see below). Make sure the map is clean: this is the version that resets will restore.
6. Have all FFA participants leave this arena, then finish setup:

   ```text
   /arena finish <id>
   /arena schemstatus <id>
   ```

   `finish` checks the spawn and bounds, saves the clean schematic and its recovery manifest, then enables and saves the arena configuration after the schematic succeeds. The spawn must be inside the saved bounds. Wait for the ready-to-join message.

7. Check `/arena info <id>`, then join with `/ffa <id>`. For an existing arena, skip creation and follow the remaining setup steps.

</Steps>

New arenas have their enabled setting turned on, but FFA entry also requires ready schematic recovery. `/arena enable <id>` does not save a schematic or bypass recovery. An enabled arena can remain hidden from the menu until `/arena finish <id>` succeeds. Use `/arena disable <id>` to take it out of rotation. `/arena tp <id>` teleports you to an arena and selects its bounds in WorldEdit/FAWE.

## Clean maps and recovery

| Command | Purpose |
| --- | --- |
| `/arena finish <id>` | Finish FFA setup, save the clean map, then enable the arena after success. |
| `/arena saveschem <id>` | Update a clean map's template without changing its enabled setting. |
| `/arena restoreschem <id>` | Restore the saved map. FFA participants must leave; everyone must be outside the bounds before pasting starts. |
| `/arena schemstatus <id>` | Show readiness, an active save/restore, or the blocking reason. |

These commands are FFA-only and require `rift.admin.arena`. Rift stores the template at `plugins/Rift/schems/<id>.schem` and its matching manifest at `plugins/Rift/schems/<id>.json`. Keep both files together in backups. The schematic includes air, block entity data, and persistent map entities.

Existing arenas need a clean template before players can enter. Repair damage or restore your world backup before the first `finish` or `saveschem`. Both commands refuse to replace a dirty recovery template: restore the arena first, make any intended edits, then save the clean map again. Restarting restores the previously saved template, so save intended map edits before restarting.

Rift marks the arena dirty before admitting a player. The last FFA participant leaving or disconnecting schedules a full restore. Rift also restores saved maps at every startup, including after a crash. The arena stays unavailable while saving or restoring, or when recovery fails. Recovery covers only the saved bounds.

Whole-map saves and restores use `ffa-recovery.blocks-per-tick` in `config.yml` (default `5000`). This controls processing speed, not map size; it is separate from `reset.blocks-per-tick` for tracked damage repairs.

## Arena names and icons

Set an arena's display name and sprite icon with:

```text
/arena rename cpvpffa Crystal PvP
/arena seticon cpvpffa end_crystal
/arena seticon cpvpffa default
```

Renaming keeps the arena ID and world unchanged. Icons use case-insensitive Rift SpriteAtlas keys, such as `end_crystal`, `mace`, or `diamond_sword`. Use `default` to clear an arena's icon override.

Browse [Minecraft atlas sprites on Gamer Geeks](https://www.gamergeeks.net/apps/minecraft/list-of-atlas-sprites) and select your Minecraft version. Rift currently accepts its registered SpriteAtlas keys; not every atlas path on that site is supported.

The native FFA selector's text, hover lore, default icon, title and close icons,
and button columns are configurable under `FFA_DIALOG_PROVIDER` in `dialogs.yml`.
Arenas without an icon override use the configured default sprite; leave the
default sprite empty to hide icons unless assigned. The default hover lore omits
the world.

To use the paginated chest selector, set `dialogs.ffa-arenas: false` in
`config.yml`, or set `dialogs.enabled: false` for all supported selectors.
Customize its title, rows, `arena-slots`, filler, arena names/lore, and navigation
under `ffa` in `menus.yml`. `ffa.arena.material: AUTO` follows the arena icon;
an explicit material overrides it for this chest screen. Dialog tooltips do not
change chest lore. Both interfaces use the same arena availability checks.
Reload with `/rift reload`, then reopen the menu. See
[Menus & Dialogs](menus-and-dialogs.mdx) for placeholders and slot rules.

## World layout

`arenas.world-mode` in `config.yml` decides where FFA arenas live.

| Mode | Result |
| --- | --- |
| `SEPARATE` (default) | Every arena gets its own void world, named `arena_<id>`. |
| `SHARED` | All arenas share one void world, named by `arenas.shared-world-name` (`arenas_void`). Place arenas far apart and set exact bounds. |

## Kit

Each FFA arena uses its own assigned kit. Equip the inventory, armor, and offhand
you want players to receive, then save that loadout for the arena:

```text
/arena setkitffa cpvpffa
```

To adjust it later, run `/arena getkitffa cpvpffa`, edit the items in your
inventory, then run `/arena setkitffa cpvpffa` again. Both commands require
`rift.admin.arena`. Repeat this setup for each FFA arena.

Joining the arena offers a five-second choice between saved layouts of its
assigned kit and **Use Arena Default**. If the choice expires, Rift applies the
arena's default arrangement. Respawns retain the selected layout. Players choose
an arrangement of that arena's kit, rather than a different kit for the arena.

`setkitffa` creates or updates kit `arena-<arena-id>` and saves its assignment in
the arena JSON's `ffaKit` field. The separate `kit` field is not the FFA kit
assignment. See [Kits](kits.mdx#ffa-arena-kits) for the full workflow.

## Rules

`ffa.yml` controls death handling.

| Setting | Default | Effect |
| --- | --- | --- |
| `rules.drop-items-on-death` | `false` | Drop the player's items on death |
| `rules.auto-respawn` | `true` | Respawn instantly without the death screen |
| `rules.auto-rekit-on-respawn` | `true` | Re-equip the kit after respawning |

`config.yml` adds an anti spawn-camp platform around the arena spawn.

```yaml
ffa-spawn-platform:
  enabled: true
  radius: 4.0
  depth: 2.0
  grace-seconds: 5
  end-grace-on-attack: true
```

Players on the platform can't deal or take damage. Stepping off grants `grace-seconds` of invulnerability, which ends early if they attack while `end-grace-on-attack` is on.

## Combat tag

`combat.yml` tags players for a few seconds after combat in FFA and RTP.

| Setting | Default | Effect |
| --- | --- | --- |
| `combat-tag.enabled` | `true` | Turn tagging on |
| `combat-tag.duration-seconds` | `5.0` | Tag length |
| `combat-tag.tagged-modes` | `FFA`, `RTP` | Modes where tagging applies |
| `restrictions.block-leave` | `true` | Block `/leave` while tagged |
| `restrictions.blocked-commands` | spawn, tpa, rtp and similar | Commands refused while tagged |
| `logout.kill-on-logout` | `true` | Kill a player who disconnects while tagged |

Give staff `rift.bypass.combattag` to exempt them. Operators don't get it automatically.

## Player commands

| Command | Description |
| --- | --- |
| `/ffa` | Open the arena menu, or join an arena by ID. |
| `/ffa join [id]` | Join an arena. |
| `/ffa leave` | Leave FFA and return to spawn. |
| `/ffakit` | Choose and arrange an FFA kit. |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| "You must be in the arena world" | `setmin`, `setmax` and `setspawn` only work while standing in that arena's world. Use `/arena tp <id>` first. |
| Players can leave the area | Check `/arena info <id>` for the bounds. New arenas default to -500..500 on X/Z until you set them. |
| Arena is enabled but the menu says "No arenas found" | Check `/arena schemstatus <id>`. Enabled FFA arenas are hidden until schematic recovery is ready. |
| No saved schematic or manifest | Configure the clean map, spawn, and bounds, then run `/arena finish <id>`. |
| WorldEdit/FAWE unavailable | Install and enable WorldEdit or FAWE, then retry. |
| Spawn missing or outside bounds | Set a spawn inside the arena with `/arena setspawn <id>`. |
| Invalid or overlapping bounds | Correct `setmin` and `setmax`; include the spawn, stay within build height, and keep shared-world FFA bounds separate. |
| Save or restore already running | Wait for completion, then check `schemstatus` again. |
| Dirty arena or players blocking a restore | Have FFA participants leave, move everyone outside the bounds, then run `/arena restoreschem <id>` before saving again. |
| Bounds changed since the template was saved | Save a new template of the clean map. For a dirty map, return to the saved bounds and restore before editing and saving again. |
| Edited JSON not applied | Run `/arena reload`. |

Recovery failures also appear in the server log as `FFA arena <id> is closed: <reason>`. Command feedback, including finish progress and completion, is configurable under `FFA_RECOVERY` in `messages.yml`.
